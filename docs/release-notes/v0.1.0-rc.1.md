# Rift Gun 0.1.0-rc.1 — Minecraft 1.21.1

- Released: 2026-08-17
- Previous: 0.1.0-beta.5
- Platform: Minecraft 1.21.1, NeoForge 21.1.140+, Java 21
- Artifact: `riftgun-1.21.1-0.1.0-rc.1.jar`

Release candidate: feature set is complete and this cycle was fixes and
polish only. A known cosmetic rendering issue remains (see Known issues).

## Changes since 0.1.0-beta.5

### Fixes

- Restore the post-transit `hasImpulse` flag (normal transit, deferred
  exits, entity relocation) — moved entities now re-sync position and
  velocity to clients immediately after travelling, as before beta.5.
- Fix a relocation reservation leak: an out-of-bounds destination aborted
  preparation without releasing the reservation, privacy grants, gun
  capacity or reserved fuel, leaving the target permanently busy.
- Fix destination selection: creating a destination while a player target
  was selected left the stale player selection in place, so portals kept
  opening to the player until the player was re-clicked.
- Restore typed NBT presence checks on save-data loading; legacy boolean
  motion-prediction saves load as TRAJECTORY/OFF again instead of
  PROJECTION.
- Reject out-of-bounds portal placements, destinations, chunk tickets and
  relocation exits with a clear message instead of attempting to load
  out-of-bounds chunks.
- Keep the strict preflight rejection when the landing spot is blocked.
- Message helper no longer recurses into itself on 1.21.x; player-list
  request guarded when disconnected.

### Additions

- Action-bar reason when a transit is refused: portal exit blocked, or
  exit portal not ready.
- Out-of-bounds destination notifications.

### Build / tooling

- Gradle 9.7 + ModDevGradle, Stonecutter 0.9.7 multi-version layout, and a
  second supported Minecraft version (26.1.2); jars now carry the Minecraft
  version in the file name.

## Known issues

- A faint light rim can appear around the portal surface (cosmetic; under
  investigation).
- Shader-pack appearance uses a conservative fallback and may vary.

## Upgrading

Back up worlds before updating. Player destinations and privacy
preferences are stored as server-side player data; visual preferences are
client-local. Saves written by earlier betas load without a migration step
in this release.
