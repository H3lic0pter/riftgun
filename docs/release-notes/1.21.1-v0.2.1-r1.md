# Rift Gun 0.2.1-r1 — Minecraft 1.21.1

- Status: Release
- Released: 2026-09-11
- Previous: 0.2.0-rc.1
- Platform: Minecraft 1.21.1, NeoForge 21.1.140+, Java 21
- Artifact: `riftgun-1.21.1-v0.2.1-r1.jar`
- SHA-256: `5355441674EA28C39B86C4F3BE70EE68ABEF4B6DB7FD2B6A71D35796DD6CAA13`
- Network protocol: `2`
- Public Addon API: `1.2.0`

Rift Gun 0.2.1-r1 turns Dimensional Navigation's Automatic Search into a
saved, reusable destination workflow and adds optional Infinite Dimensions
support on Minecraft 1.21.1. It also bounds deferred dimension-generation
work, reduces destination snapshot size, hardens queued-request lifecycle
checks, and fixes paired-portal cleanup and first-contact diagnostics.

Back up worlds before upgrading. This release advances player destination data
from schema 10 to schema 11.

## Highlights

- Automatic Search now saves a target in the virtual **Random** section instead
  of opening a portal immediately.
- Saved Automatic targets begin their bounded safe-location search only when
  used and can be reused for later portal opens.
- Added optional Infinite Dimensions `2.7.2+1.21.1-neoforge` integration for
  text-based exact-coordinate and Automatic Search targets.
- Deferred new-dimension generation is limited to one attempt per server tick
  across all players.
- Original Infinite Dimensions text remains server-side and is omitted from
  normal client snapshots.
- Closed paired portals now remove both members of the pair.
- The first blocked-route diagnostic is shown immediately; later messages keep
  the existing 20-tick rate limit.

## Saved Automatic Search Targets

Dimensional Navigation's Automatic Search mode now follows the same save-first
workflow as exact-coordinate destinations.

- Saving creates an entry in the virtual **Random** section.
- Opening the entry starts the existing bounded random-rift search in the saved
  target dimension.
- The target can be pinned or deleted.
- Random-section expansion state is persisted with the player's destination
  data.
- Automatic targets cannot be renamed, moved into ordinary groups, or shared.
- Deleting or replacing a target cancels its pending search and releases its
  chunk tickets.
- Disconnecting the owning player also cancels pending work and releases
  tickets.
- Policy, gun state, target identity, and fuel are checked again before deferred
  preparation and before the final portal open.

The search itself retains the existing cooldown, world-border, placement,
chunk-readiness, fuel, and server-authority rules from 0.2.0-rc.1.

## Infinite Dimensions Integration

When Infinite Dimensions `2.7.2+1.21.1-neoforge` is installed, Dimensional
Navigation accepts a text description as a saved target.

- Text targets support exact coordinates and Automatic Search.
- Saving a target does not generate a dimension. Generation begins only when
  the target is used.
- Existing or already-pending dimensions are reused instead of being generated
  again.
- Portal Key requirements, creative-mode exemptions, and key consumption follow
  Infinite Dimensions' own behavior.
- A request waiting on preparation is not charged or generated repeatedly on
  later ticks.
- Readiness waits stop after 200 ticks instead of remaining queued indefinitely.
- Generation failure, missing Portal Keys, changed policy, insufficient fuel,
  deletion, replacement, or disconnect cancels the request cleanly.

Each individual target accepts at most 16,384 characters. Newly saved Infinite
Dimensions text is additionally limited to 256 KiB of UTF-8 data per player.
Existing saves above that aggregate limit still load without truncation, but no
more text can be added until the saved total is reduced.

Infinite Dimensions is optional and is not bundled in the Rift Gun artifact.
Installing or removing it does not change ordinary destinations.

## Destination Data and Networking

- Player destination data advances from schema 10 to schema 11 for saved
  Automatic Search and text-target state.
- Existing exact-coordinate destinations retain their dimension, coordinates,
  yaw, group, pin state, and display name.
- Infinite Dimensions source text remains in server persistence so saved
  targets are lossless across reloads.
- Client snapshots carry only a text-target marker, not the original source
  text. This preserves UI identity without broadcasting or duplicating large
  strings.
- A regression fixture containing 256 maximum-length text destinations produces
  a 61,324-byte client snapshot.
- Missing text and intentionally empty text remain distinguishable in the client
  destination model.

The network protocol remains `2`, but mixed 0.2.0-rc.1 and 0.2.1-r1
client/server installations are unsupported. Install the exact same Rift Gun
build on every peer.

## Portal Lifecycle and Diagnostics

- Closing either member of a paired portal now cleans up the linked member as
  well, preventing a stale partner entity from remaining in the world.
- The blocked-route notification cooldown now handles its uninitialized state
  explicitly. The first contact reports immediately instead of being suppressed
  by signed tick arithmetic overflow.
- Subsequent blocked-route diagnostics remain limited to once every 20 ticks.

## Stability and Performance

- Share one new-dimension generation budget across all queued players for each
  server tick.
- Preserve first-in request order while advancing queued searches.
- Do not spend the generation budget when a target dimension already exists or
  another request is already preparing it.
- Treat a failed generation attempt as the tick's generation work, preventing a
  burst of fallback attempts in the same tick.
- Keep generation state separate per server instance.
- Cancel absent-player searches and release their chunk tickets.
- Revalidate policy and fuel after queueing so changed conditions cannot open or
  charge a stale request.
- Avoid sending persisted Infinite Dimensions text in routine client snapshots,
  bounding network and allocation cost for large destination libraries.
- Added lifecycle, generation-budget, persistence, snapshot-size, UTF-8 budget,
  cancellation, timeout, policy, fuel, and platform-stub regression tests.

Infinite Dimensions exposes synchronous dimension creation. The shared budget
prevents several new generations from stacking in one server tick, but one new
dimension can still cause a long tick. This release does not claim asynchronous
generation or eliminate all generation stalls.

## Public Addon API 1.2.0

The public Addon API is unchanged from 0.2.0-rc.1. This release ships:

- `riftgun-1.21.1-v0.2.1-r1-api.jar`
- `riftgun-1.21.1-v0.2.1-r1-api-sources.jar`

The API continues to expose typed portal-open requests, Coordinate Note
creation, dimension labels, portal-open policies, and transit authorization.
Both API artifacts include `META-INF/LICENSE`; the binary artifact includes the
runtime bridge required by `RiftGunTransitContext`.

Do not install the `-api` or `-api-sources` artifacts in `mods`. They are for
addon developers. The normal Rift Gun JAR already contains the API runtime.

## Configuration Changes

No new configuration file is introduced. NeoForge may use:

- `config/riftgun-client.toml`: client-local visuals, sounds, preview choices,
  and optional dynamic-light brightness.
- `config/riftgun-common.toml`: 1.21.1 Create recipe integration.
- `<world>/serverconfig/riftgun-server.toml`: server-authoritative gameplay,
  module, fuel, dimensional traversal, map-waypoint integration, privacy,
  placement, readiness, and diagnostics settings.

Existing settings keep backward-safe defaults. Infinite Dimensions behavior is
available only while that optional mod is installed.

## Upgrading from 0.2.0-rc.1

1. Back up the world, player data, and configuration files.
2. Stop the server and all clients.
3. Remove the old Rift Gun JAR before copying the new artifact; do not keep two
   Rift Gun versions in `mods`.
4. Install the exact same Rift Gun `0.2.1-r1` build on the server and every
   client.
5. To use text-based targets, install the matching Infinite Dimensions version
   on both the server and clients.
6. Start the server and verify existing exact-coordinate destinations, saved
   groups, pin state, Portal Guns, modules, and fuel.
7. Test a saved Automatic Search target before reopening a public server.

Schema 11 data should not be written back by 0.2.0-rc.1. Restore a pre-upgrade
backup when rolling back.

## Known Limitations

- Infinite Dimensions creates dimensions synchronously through its upstream
  API. A single new dimension can still produce a long server tick.
- No live-server performance profiling was completed for this release package;
  profile representative modpacks before public deployment.
- Infinite Dimensions integration is available only on the 1.21.1 artifact.
- Text targets cannot be previewed or resolved without Infinite Dimensions
  installed.
- Automatic targets are intentionally read-only apart from pinning and deletion.
- Portal placement remains non-destructive. Cramped or obstructed destinations
  may fail instead of moving or breaking blocks.
- Unregistered shader packs retain the conservative rendering fallback described
  in the 0.2.0-rc.1 notes.
- Xaero's Minimap integration still targets a verified implementation range
  rather than a stable independent waypoint API.
- Public Addon API stability is not guaranteed before Rift Gun 1.0.0.
