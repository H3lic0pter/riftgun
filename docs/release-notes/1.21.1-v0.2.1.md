# Rift Gun 0.2.1 — Minecraft 1.21.1

- Previous: 0.2.0-rc.1
- Platform: Minecraft 1.21.1, NeoForge 21.1.140+, Java 21
- Artifact: `riftgun-1.21.1-v0.2.1.jar`
- Public Addon API: `1.2.0` (unchanged)

## Highlights

- Automatic Search now saves a reusable target in the Random section. Searching
  starts when the target is used, instead of immediately opening a portal.
- Automatic targets support pinning and deletion, with persisted section
  expansion state. Editing, moving to another group, and sharing are unavailable.
- Added optional Infinite Dimensions integration for `2.7.2+1.21.1-neoforge`.
  Save a text-based dimension target with exact coordinates or Automatic Search;
  dimension generation is deferred until the target is used.
- Portal Key requirements and consumption follow Infinite Dimensions settings
  and creative-mode rules. Infinite Dimensions is optional and is not bundled.

## Stability and Performance

- Limit new Infinite Dimensions generation to one attempt per server tick across
  all queued players. Existing and already-pending dimensions do not consume this
  generation budget; repeated waiting ticks do not generate or charge again.
- Cancel stale requests when a target changes, is deleted, or its player leaves.
  Recheck authorization and fuel before queued generation and final opening.
- Clean up both members of a closed paired portal instead of leaving a stale
  partner entity behind.
- Show the first blocked-route diagnostic immediately; later notices remain
  rate-limited to once per 20 ticks.
- Bound deferred dimension readiness waits to 200 ticks.
- Keep original dimension text in server persistence, not routine client
  snapshots. A regression fixture with 256 text targets produces a 61,324-byte
  snapshot instead of repeating every source text.
- Limit newly saved dimension text to 256 KiB of UTF-8 data per player, in
  addition to the 16,384-character per-target limit. Existing saved text loads
  without truncation.

## Upgrade Notes

Back up worlds, player data, and configuration before upgrading. Replace the old
mod JAR, and install the same `0.2.1` build on the server and all clients.
Do not install the `-api` or `-api-sources` artifacts in `mods`; those are for
addon developers.

Player data schema advances from 10 to 11. Existing exact-coordinate targets
retain their coordinates. Restore a pre-upgrade backup when rolling back;
older builds do not understand the new deferred target semantics.

## Known Limitations

Infinite Dimensions generation still runs synchronously in its upstream API.
The per-tick budget prevents stacked generation attempts, but a single new
dimension can still cause a long server tick. No live-server performance claim
is made; in-game smoke testing and profiling remain recommended before deployment.

Placement remains non-destructive: obstructed or unavailable destinations may
fail instead of modifying blocks. Other platform and optional-integration
limitations from 0.2.0-rc.1 continue to apply.
