# Rift Gun 0.2.1-r1 — Minecraft 26.1.2

- Status: Release
- Released: 2026-09-11
- Previous: 0.2.0-rc.1
- Platform: Minecraft 26.1.2, NeoForge 26.1.2.95+, Java 25
- Artifact: `riftgun-26.1.2-v0.2.1-r1.jar`
- SHA-256: `B2B9821CE6AF8E98CC02621DAD6FDE1F5FE645155B760F63241EDA2D4CC27E5E`
- Network protocol: `3`
- Public Addon API: `1.2.0`

Rift Gun 0.2.1-r1 turns Dimensional Navigation's Automatic Search into a
saved, reusable destination workflow. It also hardens queued-request lifecycle
checks, reduces destination snapshot size, and fixes paired-portal cleanup and
first-contact diagnostics.

Back up worlds before upgrading. This release advances player destination data
from schema 10 to schema 11.

## Highlights

- Automatic Search now saves a target in the virtual **Random** section instead
  of opening a portal immediately.
- Saved Automatic targets begin their bounded safe-location search only when
  used and can be reused for later portal opens.
- Pending searches are cancelled when their target changes, is deleted, or the
  owning player disconnects.
- Queued opens recheck policy, gun state, target identity, and fuel before
  continuing.
- Closed paired portals now remove both members of the pair.
- The first blocked-route diagnostic is shown immediately; later messages keep
  the existing 20-tick rate limit.

## Saved Automatic Search Targets

Dimensional Navigation's Automatic Search mode now follows the same save-first
workflow as exact-coordinate destinations.

- Saving creates an entry in the virtual **Random** section.
- Opening the entry starts the existing bounded random-rift search in the saved
  target dimension.
- The target can be pinned or deleted.
- Random-section expansion state is persisted with the player's destination
  data.
- Automatic targets cannot be renamed, moved into ordinary groups, or shared.
- Deleting or replacing a target cancels its pending search and releases its
  chunk tickets.
- Disconnecting the owning player also cancels pending work and releases
  tickets.
- Policy, gun state, target identity, and fuel are checked again before deferred
  preparation and before the final portal open.

The search itself retains the existing cooldown, world-border, placement,
chunk-readiness, fuel, and server-authority rules from 0.2.0-rc.1.

## Destination Data and Networking

- Player destination data advances from schema 10 to schema 11 for saved
  Automatic Search target state.
- Existing exact-coordinate destinations retain their dimension, coordinates,
  yaw, group, pin state, and display name.
- The destination model preserves text-target identity without copying source
  text into routine client snapshots.
- Missing text and intentionally empty text remain distinguishable in the client
  destination model.
- Shared text-data safeguards allow existing saves to load without truncation.

Network protocol `3` adds the gun's pairing mode to its synchronized visual state.
Protocol `2` builds are rejected during connection negotiation. Install the exact
same Rift Gun build on every peer, including earlier builds labelled 0.2.1-r1.

## Portal Lifecycle and Diagnostics

- Closing either member of a paired portal now cleans up the linked member as
  well, preventing a stale partner entity from remaining in the world.
- The blocked-route notification cooldown now handles its uninitialized state
  explicitly. The first contact reports immediately instead of being suppressed
  by signed tick arithmetic overflow.
- Subsequent blocked-route diagnostics remain limited to once every 20 ticks.

## Stability and Performance

- Preserve first-in request order while advancing queued searches.
- Cancel absent-player searches and release their chunk tickets.
- Revalidate policy and fuel after queueing so changed conditions cannot open or
  charge a stale request.
- Bound deferred preparation waits to 200 ticks.
- Avoid copying persisted text source data into routine client snapshots.
- Added lifecycle, persistence, cancellation, timeout, policy, fuel, and
  platform-stub regression tests.
- Keep Infinite Dimensions preparation explicitly unavailable on this platform
  instead of attempting unsupported generation.

## Platform Differences

Infinite Dimensions text-based target generation is not available in the
Minecraft 26.1.2 artifact. This build supports saved Automatic Search targets
for dimensions already present on the server.

Create Mechanical Mixer and Immersive Portals integrations remain specific to
the 1.21.1 build. The 26.1.2 artifact retains its existing JourneyMap, Xaero's
Minimap, JEI, LambDynamicLights, and shader compatibility paths.

## Public Addon API 1.2.0

The public Addon API is unchanged from 0.2.0-rc.1. This release ships:

- `riftgun-26.1.2-v0.2.1-r1-api.jar`
- `riftgun-26.1.2-v0.2.1-r1-api-sources.jar`

The API continues to expose typed portal-open requests, Coordinate Note
creation, dimension labels, portal-open policies, and transit authorization.
Both API artifacts include `META-INF/LICENSE`; the binary artifact includes the
runtime bridge required by `RiftGunTransitContext`.

Do not install the `-api` or `-api-sources` artifacts in `mods`. They are for
addon developers. The normal Rift Gun JAR already contains the API runtime.

## Configuration Changes

No new configuration file is introduced. NeoForge may use:

- `config/riftgun-client.toml`: client-local visuals, sounds, preview choices,
  and optional dynamic-light brightness.
- `<world>/serverconfig/riftgun-server.toml`: server-authoritative gameplay,
  module, fuel, dimensional traversal, map-waypoint integration, privacy,
  placement, readiness, and diagnostics settings.

The 1.21.1-only `riftgun-common.toml` Create integration file is not generated
by the 26.1.2 build. Existing settings keep backward-safe defaults.

## Upgrading from 0.2.0-rc.1

1. Back up the world, player data, and configuration files.
2. Stop the server and all clients.
3. Remove the old Rift Gun JAR before copying the new artifact; do not keep two
   Rift Gun versions in `mods`.
4. Install the exact same Rift Gun `0.2.1-r1` build on the server and every
   client.
5. Start the server and verify existing exact-coordinate destinations, saved
   groups, pin state, Portal Guns, modules, and fuel.
6. Test a saved Automatic Search target before reopening a public server.

Schema 11 data should not be written back by 0.2.0-rc.1. Restore a pre-upgrade
backup when rolling back.

## Known Limitations

- Infinite Dimensions text-based targets are not available on 26.1.2.
- The 26.1.2 build is newer and has received less real-world testing than the
  1.21.1 build.
- No live-server performance profiling was completed for this release package.
- Create and Immersive Portals integrations are not included in this node.
- Automatic targets are intentionally read-only apart from pinning and deletion.
- Portal placement remains non-destructive. Cramped or obstructed destinations
  may fail instead of moving or breaking blocks.
- Unregistered shader packs retain the conservative rendering fallback described
  in the 0.2.0-rc.1 notes.
- Xaero's Minimap integration still targets a verified implementation range
  rather than a stable independent waypoint API.
- Public Addon API stability is not guaranteed before Rift Gun 1.0.0.
